第2章　問1

AWSの責任共有モデルで「クラウドのセキュリティ」（AWSの責任）に含まれるものはどれ？

  1. ア　IAMポリシーで付与する権限の範囲
  2. イ　EC2インスタンスのゲストOSへのパッチ適用
  3. ウ　AWSのデータセンターに設置された物理ホストの保守
  4. エ　S3バケットに保存するデータの分類
答えと解説を見る

正解：ウ　AWSのデータセンターに設置された物理ホストの保守

AWSはクラウドを動かす施設・ハードウェア・ネットワーク・仮想化基盤を守る責任を持つ。IAMの権限設定、ゲストOSのパッチ、データの分類は利用者側の「クラウドにおけるセキュリティ」に当たる。

第2章　問2

ある会社はAmazon EC2でWebサーバーを動かしている。責任共有モデルで、この会社が担当するものはどれ？

  1. ア　ハイパーバイザーの脆弱性対応
  2. イ　データセンターへの入館管理
  3. ウ　ホストサーバーのディスクの物理的な廃棄
  4. エ　インスタンス上のOSとアプリケーションの更新
答えと解説を見る

正解：エ　インスタンス上のOSとアプリケーションの更新

EC2はIaaSなので、ゲストOSから上（OS・ミドルウェア・アプリ）の更新は利用者の責任になる。ハイパーバイザー、入館管理、物理ディスクの廃棄はAWSが担当する。

第2章　問3

Amazon RDSを使う場合、責任共有モデルでAWSが担当するものはどれ？

  1. ア　データベースエンジンが動くOSへのパッチ適用
  2. イ　データベースのユーザーとそのパスワードの管理
  3. ウ　データベースへ接続を許可するセキュリティグループの設定
  4. エ　どのテーブルに個人情報を入れるかの判断
答えと解説を見る

正解：ア　データベースエンジンが動くOSへのパッチ適用

RDSはマネージドサービスなので、基盤のOSやデータベースエンジンのパッチ適用はAWSが行う（利用者はメンテナンスウィンドウを選べる）。DBユーザー、セキュリティグループ、保存するデータの扱いは利用者の責任。

第2章　問4

AWS Lambdaで関数を動かす場合、責任共有モデルで利用者が担当するものはどれ？

  1. ア　関数を実行するサーバーのOSの更新
  2. イ　関数のコードと、関数に付与するIAMロールの権限
  3. ウ　実行環境のランタイムを動かす物理ホストの管理
  4. エ　関数を実行するためのキャパシティの物理的な調達
答えと解説を見る

正解：イ　関数のコードと、関数に付与するIAMロールの権限

Lambdaではサーバー・OS・実行基盤はAWSが管理するため、利用者が担うのは主に自分のコードと、関数に与える権限（IAM）、扱うデータになる。OSや物理ホスト、キャパシティの調達はAWSの担当。

第2章　問5

Amazon EC2、Amazon RDS、AWS Lambdaを比べたとき、利用者が担当するセキュリティ作業が一般的に最も多いのはどれ？

  1. ア　Amazon EC2
  2. イ　Amazon RDS
  3. ウ　AWS Lambda
  4. エ　3つとも同じ
答えと解説を見る

正解：ア　Amazon EC2

EC2は利用者がOS以上を管理するため、パッチ適用やソフトウェアの設定など担当範囲が最も広い。RDSやLambdaのようにマネージド度が高いサービスほど、AWSの担当範囲が広がり利用者の作業は減る。

第2章　問6

責任共有モデルで、AWSと利用者の両方が責任を持つ「共有コントロール」の例はどれ？

  1. ア　物理的・環境的なコントロール
  2. イ　データセンターの電源と空調
  3. ウ　利用者のデータの分類
  4. エ　パッチ管理
答えと解説を見る

正解：エ　パッチ管理

パッチ管理は共有コントロールの例で、AWSはインフラのパッチを、利用者はゲストOSやアプリのパッチを担当する。物理的・環境的なコントロールはAWSから引き継ぐもの、データの分類は利用者固有の責任。

第2章　問7

Amazon S3を使う場合、責任共有モデルで利用者が担当するものはどれ？

  1. ア　S3を構成するストレージ機器の冗長化
  2. イ　S3のサービス自体を動かすソフトウェアの更新
  3. ウ　バケットポリシーやパブリックアクセスの設定
  4. エ　S3が置かれた施設の監視カメラの運用
答えと解説を見る

正解：ウ　バケットポリシーやパブリックアクセスの設定

S3では、誰にアクセスを許すか（バケットポリシー、ブロックパブリックアクセスなど）や暗号化の選び方は利用者が決める。ストレージ機器の冗長化、サービスのソフトウェア、施設の監視はAWSの担当。

第2章　問8

EC2インスタンスに接続したEBSボリュームの暗号化について、責任共有モデルの考え方として正しいものはどれ？

  1. ア　AWSがすべてのボリュームの暗号化キーを利用者に代わって選ぶ責任を持つ
  2. イ　暗号化を有効にするかどうかは利用者が決めて設定する
  3. ウ　暗号化はAWSの責任なので利用者は何もできない
  4. エ　暗号化の設定は物理的なセキュリティの一部としてAWSが行う
答えと解説を見る

正解：イ　暗号化を有効にするかどうかは利用者が決めて設定する

AWSは暗号化の仕組み（機能）を提供するが、それを使うかどうか、どのキーを使うかを決めて設定するのは利用者の責任。データを守る設定は「クラウドにおけるセキュリティ」に当たる。

第2章　問9

責任共有モデルで、利用者がどのサービスを使う場合でも常に利用者の責任になるものはどれ？

  1. ア　利用者のデータと、そのデータへのアクセス権の管理
  2. イ　グローバルインフラストラクチャの可用性
  3. ウ　仮想化レイヤーの分離
  4. エ　ネットワーク機器のファームウェアの更新
答えと解説を見る

正解：ア　利用者のデータと、そのデータへのアクセス権の管理

どのサービスでも、自分のデータの扱いと、誰がそれにアクセスできるか（IAMなど）の管理は利用者の責任として残る。インフラの可用性、仮想化の分離、ネットワーク機器の更新はAWSが担当する。

第2章　問10（2つ選ぶ）

責任共有モデルについて正しい説明を選べ。2つ選んで。

  1. ア　AWSは利用者のIAMユーザーに付与する権限を決める
  2. イ　AWSはハードウェアやグローバルインフラストラクチャのセキュリティに責任を持つ
  3. ウ　利用者はAWSのデータセンターの物理的なアクセス管理を行う
  4. エ　マネージドサービスほど、利用者が担当する範囲は小さくなる傾向がある
  5. オ　サービスを問わず、OSのパッチ適用は常にAWSが行う
答えと解説を見る

正解：イ　AWSはハードウェアやグローバルインフラストラクチャのセキュリティに責任を持つ
エ　マネージドサービスほど、利用者が担当する範囲は小さくなる傾向がある

AWSはハードウェアやグローバルインフラを守り、マネージド度が高いサービスほど利用者の担当範囲は小さくなる。物理アクセスはAWSの担当、EC2のゲストOSのパッチは利用者の担当、IAMの権限も利用者が決める。

第2章　問11

セキュリティグループのルールを誤って全開放にしたため、EC2インスタンスが外部から攻撃を受けた。責任共有モデルでこの設定の責任を持つのは誰？

  1. ア　AWS
  2. イ　AWS Marketplaceの販売者
  3. ウ　利用者
  4. エ　インターネットサービスプロバイダー
答えと解説を見る

正解：ウ　利用者

セキュリティグループなどのファイアウォール設定は利用者が行うため、誤った設定の責任は利用者にある。AWSはセキュリティグループという機能そのものが正しく動くことに責任を持つ。

第2章　問12

AWSが管理するインフラについて、利用者が自社の監査で使う「AWSから引き継ぐコントロール（継承されたコントロール）」の例はどれ？

  1. ア　アプリケーションの入力値チェック
  2. イ　IAMユーザーのパスワードポリシー
  3. ウ　ゲストOSのファイアウォール設定
  4. エ　データセンターの物理的・環境的なコントロール
答えと解説を見る

正解：エ　データセンターの物理的・環境的なコントロール

物理的・環境的なコントロールはAWSが完全に実施しており、利用者はそれをそのまま引き継いで自社のコンプライアンスに使える。入力値チェック、パスワードポリシー、ゲストOSの設定は利用者が実施するもの。

第2章　問13

監査人から、AWSのSOCレポートやISO認証の証明書を提出するよう求められた。これらの資料をダウンロードできるサービスはどれ？

  1. ア　AWS Config
  2. イ　AWS Artifact
  3. ウ　Amazon Inspector
  4. エ　AWS Trusted Advisor
答えと解説を見る

正解：イ　AWS Artifact

AWS Artifactは、AWSの第三者監査レポート（SOC、PCIなど）や認証の資料をセルフサービスで入手できるポータル。Configは自分のリソース設定の記録、Inspectorは脆弱性の検査、Trusted Advisorはベストプラクティスの確認に使う。

第2章　問14

ある医療系の会社は、AWSとHIPAAに関するBusiness Associate Addendum（BAA）などの契約を確認・締結したい。どのサービスを使うべき？

  1. ア　AWS Artifact
  2. イ　AWS Audit Manager
  3. ウ　AWS Organizations
  4. エ　AWS Control Tower
答えと解説を見る

正解：ア　AWS Artifact

AWS Artifactにはレポートのほかに「契約（Agreements）」の機能があり、BAAなどのAWSとの契約を確認・受け入れ・管理できる。Audit Managerは自社の監査証跡の収集、OrganizationsとControl Towerは複数アカウントの管理に使う。

第2章　問15

「先週の金曜日に誰がS3バケットを削除したか」を調べたい。どのサービスの記録を見るべき？

  1. ア　Amazon CloudWatch のメトリクス
  2. イ　AWS Artifact
  3. ウ　Amazon Macie
  4. エ　AWS CloudTrail
答えと解説を見る

正解：エ　AWS CloudTrail

AWS CloudTrailはAWSアカウント内のAPI呼び出し（誰が・いつ・どこから・何をしたか）を記録するので、削除操作の実行者を追跡できる。CloudWatchのメトリクスは性能の数値、Artifactは監査資料、MacieはS3内の機密データの検出に使う。

第2章　問16

リソースの設定が時間とともにどう変わったかを記録し、「EBSボリュームが暗号化されているか」などのルールに沿っているかを継続的に評価できるサービスはどれ？

  1. ア　AWS CloudTrail
  2. イ　AWS Shield
  3. ウ　AWS Config
  4. エ　Amazon Cognito
答えと解説を見る

正解：ウ　AWS Config

AWS Configはリソースの設定の履歴を記録し、Configルールで望ましい設定に準拠しているかを評価する。CloudTrailは「誰が操作したか」のAPI記録が中心で、設定の準拠評価そのものはConfigの役割。

第2章　問17

AWS CloudTrailとAWS Configの違いの説明として正しいものはどれ？

  1. ア　CloudTrailはAPIの操作履歴を、Configはリソースの設定状態とその変化を記録する
  2. イ　CloudTrailはリソースの設定状態を、ConfigはAPIの操作履歴を記録する
  3. ウ　どちらもネットワークの通信内容（パケット）を記録する
  4. エ　どちらもAWSの第三者監査レポートを提供する
答えと解説を見る

正解：ア　CloudTrailはAPIの操作履歴を、Configはリソースの設定状態とその変化を記録する

CloudTrailは「誰が何の操作をしたか」、Configは「リソースがどんな設定で、いつどう変わったか」に注目する。組み合わせると、設定変更とそれを行った人を結びつけて調べられる。

第2章　問18

ある会社は、自社のAWSアカウントの設定がPCI DSSなどのセキュリティ基準に沿っているかを自動でチェックし、結果を1か所で確認したい。どのサービスが最適？

  1. ア　AWS Artifact
  2. イ　AWS Security Hub
  3. ウ　Amazon Detective
  4. エ　AWS Firewall Manager
答えと解説を見る

正解：イ　AWS Security Hub

AWS Security Hub（設定のチェック機能は AWS Security Hub CSPM）は、AWSのベストプラクティスやPCI DSSなどの基準に沿ってアカウントの設定を自動でチェックし、結果をまとめて表示する。ArtifactはAWS自身の監査レポートを入手する場、Detectiveはセキュリティの問題の調査、Firewall ManagerはWAFなどのルールの一括管理に使う。

第2章　問19

AWS Organizationsのサービスコントロールポリシー（SCP）の説明として正しいものはどれ？

  1. ア　個々のIAMユーザーに権限を付与するためのポリシー
  2. イ　EC2インスタンスへの通信を許可・拒否するファイアウォールのルール
  3. ウ　メンバーアカウントで使える権限の上限を定めるもので、それ自体は権限を付与しない
  4. エ　S3バケットに付けて外部アカウントにアクセスを許可するポリシー
答えと解説を見る

正解：ウ　メンバーアカウントで使える権限の上限を定めるもので、それ自体は権限を付与しない

SCPは組織内のアカウントで「使える操作の最大範囲」を決めるガードレールで、実際の権限はIAMポリシーなどで別に与える必要がある。ファイアウォールのルールはセキュリティグループなど、バケットに付けるのはバケットポリシー。

第2章　問20

ある会社は、組織内のすべての開発用アカウントで、特定のリージョン以外にリソースを作れないようにしたい。各アカウントの管理者でもこの制限を外せないようにするには、何を使うべき？

  1. ア　各アカウントのIAMユーザーにパスワードポリシーを設定する
  2. イ　セキュリティグループ
  3. ウ　AWS Trusted Advisorのチェック
  4. エ　AWS Organizationsのサービスコントロールポリシー（SCP）
答えと解説を見る

正解：エ　AWS Organizationsのサービスコントロールポリシー（SCP）

SCPはOUやアカウント単位で適用され、メンバーアカウント内の管理者を含むすべてのユーザーとロールの操作範囲を制限できる。パスワードポリシーやセキュリティグループでは操作できるリージョンを組織全体で制限できず、Trusted Advisorは確認だけで制限はしない。
