第1章　クラウドの概念

第1章　問1

AWSが挙げる「クラウドコンピューティングの6つの利点」に含まれるものはどれ？

  1. ア　すべてのデータが自動で暗号化される
  2. イ　ソフトウェアのライセンスが不要になる
  3. ウ　キャパシティの予測が不要になる
  4. エ　システムの障害が起きなくなる
答えと解説を見る

正解：ウ　キャパシティの予測が不要になる

6つの利点の1つに「キャパシティの予測が不要になる（Stop guessing capacity）」がある。暗号化やライセンス不要は利点として挙げられておらず、障害がゼロになることもない。

第1章　問2（2つ選ぶ）

クラウドコンピューティングの6つの利点に含まれるものはどれ？2つ選んで。

  1. ア　長期契約で料金を必ず固定できる
  2. イ　ハードウェアを自社の資産として所有できる
  3. ウ　固定費を変動費に変えられる
  4. エ　数分でグローバルに展開できる
  5. オ　利用者がデータセンターの物理的な警備を担当できる
答えと解説を見る

正解：ウ　固定費を変動費に変えられる
エ　数分でグローバルに展開できる

「固定費を変動費に変える」「数分でグローバルに展開」はどちらも6つの利点に含まれる。物理的な警備はAWSの担当で、ハードウェアの所有や料金の固定はクラウドの利点ではない。

第1章　問3

AWSが多くの利用者のリソースをまとめて運用することで、利用者がより安い従量料金を受けられる。この利点を何という？

  1. ア　伸縮性
  2. イ　高可用性
  3. ウ　フォールトトレランス
  4. エ　規模の経済
答えと解説を見る

正解：エ　規模の経済

多数の利用者の利用量を集約することでAWSのコストが下がり、それが料金の引き下げにつながる。これが「規模の経済」の利点。伸縮性や高可用性はシステムの性質の話で、価格の仕組みではない。

第1章　問4

ある会社では、新しいサーバーを用意するのに調達から設置まで数週間かかっていた。AWSに移ると数分で用意できるようになった。これはクラウドのどの利点にあたる？

  1. ア　速度と俊敏性の向上
  2. イ　規模の経済
  3. ウ　データセンターの運用・保守への投資が不要
  4. エ　フォールトトレランス
答えと解説を見る

正解：ア　速度と俊敏性の向上

リソースを数分で用意でき、試行錯誤のスピードが上がるのは「速度と俊敏性（スピードとアジリティ）」の利点。規模の経済は料金の安さ、フォールトトレランスは障害時も止まらない性質を指す。

第1章　問5

「伸縮性（エラスティシティ）」と「拡張性（スケーラビリティ）」の違いの説明として最も適切なものはどれ？

  1. ア　伸縮性はリソースを減らすことだけ、拡張性はリソースを増やすことだけを指す
  2. イ　伸縮性はオンプレミスの性質、拡張性はクラウドだけの性質
  3. ウ　伸縮性は需要の増減に合わせてリソースを自動で増やしたり減らしたりすること、拡張性は需要の増加に対応できるようにリソースを増やせること
  4. エ　伸縮性はデータのバックアップ、拡張性はデータの暗号化を指す
答えと解説を見る

正解：ウ　伸縮性は需要の増減に合わせてリソースを自動で増やしたり減らしたりすること、拡張性は需要の増加に対応できるようにリソースを増やせること

伸縮性は需要の変化に応じて自動で増減し、余った分を減らしてコストを抑える点が特徴。拡張性は負荷の増加に合わせて規模を大きくできる能力を指す。どちらもバックアップや暗号化とは関係がない。

第1章　問6

ECサイトの会社は、セールの日だけアクセスが10倍になる。ピークに合わせてサーバーを常に用意しておくと、普段はほとんどが使われない。クラウドのどの特性を使えばこの無駄を減らせる？

  1. ア　データ主権
  2. イ　伸縮性
  3. ウ　ライセンス持ち込み
  4. エ　物理的な分離
答えと解説を見る

正解：イ　伸縮性

伸縮性を活かせば、ピーク時だけリソースを増やし、普段は減らして使った分だけ支払える。データ主権はデータの保管場所の話で、ライセンス持ち込みや物理的な分離はアクセス変動への対応とは関係がない。

第1章　問7

「高可用性」と「フォールトトレランス（耐障害性）」の違いとして正しいものはどれ？

  1. ア　高可用性はセキュリティを高めること、フォールトトレランスはコストを下げること
  2. イ　高可用性はオンプレミス専用、フォールトトレランスはクラウド専用の考え方
  3. ウ　両者はまったく同じ意味で、違いはない
  4. エ　高可用性は停止時間をできるだけ短くすること、フォールトトレランスは一部が故障してもサービスを止めずに動き続けること
答えと解説を見る

正解：エ　高可用性は停止時間をできるだけ短くすること、フォールトトレランスは一部が故障してもサービスを止めずに動き続けること

高可用性は短い停止はありえても、全体として使える時間を最大にする考え方。フォールトトレランスは部品の故障が起きても中断なく動き続けることを目指す、より厳しい性質。どちらもセキュリティやコストそのものを指す言葉ではない。

第1章　問8

オンプレミスでは数年先の需要を見込んでサーバーを買う必要があり、買いすぎや不足が起きていた。クラウドではこの問題を解決できる。これを表すAWSの利点はどれ？

  1. ア　キャパシティの予測が不要になる
  2. イ　数分でグローバルに展開できる
  3. ウ　規模の経済の恩恵を受けられる
  4. エ　データセンターの運用・保守への投資が不要
答えと解説を見る

正解：ア　キャパシティの予測が不要になる

必要なときに必要な分だけ増減できるので、事前に容量を見積もって買う必要がない。これが「キャパシティの予測が不要」の利点。グローバル展開や規模の経済は別の利点を指す。

ある会社は、サーバーの設置、電源や空調の管理といった作業をやめ、自社の製品開発に人を集中させたい。これはクラウドのどの利点にあたる？

  1. ア　数分でグローバルに展開できる
  2. イ　キャパシティの予測が不要になる
  3. ウ　データセンターの運用・保守への投資が不要になる
  4. エ　規模の経済の恩恵を受けられる
答えと解説を見る

正解：ウ　データセンターの運用・保守への投資が不要になる

ラックの設置や電源・空調の管理といった重労働から解放され、顧客や事業に集中できるのが「データセンターの運用・保守にお金をかけなくてよい」利点。ほかの選択肢も利点だが、この場面を最もよく表すものではない。

  1. ア　固定費を変動費に変えられる
  2. イ　数分でグローバルに展開できる

  4. エ　伸縮性

正解：イ　数分でグローバルに展開できる

世界中のリージョンを使えば、海外の利用者の近くにすぐアプリを置ける。これが「数分でグローバルに展開」の利点。伸縮性は台数の増減、フォールトトレランスは障害への強さの話。

第1章　問11

AWS Well-Architected フレームワークの6つの柱に含まれないものはどれ？

  1. ア　持続可能性
  2. イ　運用上の優秀性
  3. ウ　コスト最適化
  4. エ　スケーラビリティ
答えと解説を見る

正解：エ　スケーラビリティ

6つの柱は「運用上の優秀性」「セキュリティ」「信頼性」「パフォーマンス効率」「コスト最適化」「持続可能性」。スケーラビリティは大切な考え方だが、独立した柱ではない。

第1章　問12

Well-Architected フレームワークで、障害から自動で復旧する、需要に応じて変化するなど「期待どおりに機能を果たし続ける」ことを扱う柱はどれ？

  1. ア　信頼性
  2. イ　パフォーマンス効率
  3. ウ　運用上の優秀性
  4. エ　セキュリティ
答えと解説を見る

正解：ア　信頼性

信頼性の柱は、ワークロードが意図した機能を正しく一貫して果たすことを扱い、障害からの自動復旧や復旧手順のテストなどが含まれる。パフォーマンス効率はリソースを効率よく使うこと、運用上の優秀性は運用と改善の仕組みを扱う。

第1章　問13

Well-Architected フレームワークで、クラウドのワークロードが環境に与える影響（エネルギー消費など）を減らすことに焦点を当てた柱はどれ？

  1. ア　コスト最適化
  2. イ　パフォーマンス効率
  3. ウ　持続可能性
  4. エ　信頼性
答えと解説を見る

正解：ウ　持続可能性

持続可能性の柱は、エネルギー消費の削減や効率化によって環境への影響を最小にすることを扱う。コスト最適化は費用、パフォーマンス効率は性能面の効率を扱う柱。

第1章　問14

Well-Architected フレームワークの「運用上の優秀性」の柱に最も関係が深い取り組みはどれ？

  1. ア　使っていないリソースを削除して料金を下げる
  2. イ　運用作業をコードとして定義し、小さな変更をこまめに行う
  3. ウ　保存データと通信を暗号化する
  4. エ　処理に最も合ったインスタンスタイプを選ぶ
答えと解説を見る

正解：イ　運用作業をコードとして定義し、小さな変更をこまめに行う

運用上の優秀性は、運用をコード化する、小さく元に戻せる変更を頻繁に行う、失敗から学ぶといった運用と継続的な改善を扱う。不要リソースの削除はコスト最適化、暗号化はセキュリティ、インスタンス選びはパフォーマンス効率にあたる。

ある会社は、動画変換の処理に最も適したコンピューティングの種類やサイズを選び、技術の進化に合わせて見直したい。Well-Architected フレームワークのどの柱に当たる？

  1. ア　持続可能性

  4. エ　パフォーマンス効率

正解：エ　パフォーマンス効率

パフォーマンス効率の柱は、要件に合ったリソースを効率よく使い、需要や技術の変化に合わせて選び直すことを扱う。信頼性は障害への対応、セキュリティは情報や資産の保護を扱う。

第1章　問16

自社のワークロードがAWSのベストプラクティスに沿っているかを、質問に答える形で見直し、改善点を見つけられるサービスはどれ？

  1. ア　AWS Well-Architected Tool
  2. イ　AWS DataSync

正解：ア　AWS Well-Architected Tool

AWS Well-Architected Tool は、Well-Architected フレームワークに基づく質問に答えてワークロードをレビューし、リスクと改善計画を確認できる。DataSync はファイルの転送、Outposts はオンプレミスでAWSを動かすための製品、Transform MGN はサーバーの移行に使う。

第1章　問17（2つ選ぶ）

Well-Architected フレームワークの柱と、その柱が扱う内容の組み合わせとして正しいものはどれ？2つ選んで。

  1. ア　持続可能性：システムを長期契約で固定して運用する
  2. イ　運用上の優秀性：すべての作業を手動で慎重に行う
  3. ウ　セキュリティ：データ・システム・資産を保護する
  4. エ　コスト最適化：不要な費用を避け、最小の費用で価値を出す
  5. オ　信頼性：最新の技術を常に使い続ける
答えと解説を見る

正解：ウ　セキュリティ：データ・システム・資産を保護する
エ　コスト最適化：不要な費用を避け、最小の費用で価値を出す

セキュリティはデータやシステムの保護、コスト最適化は不要な支出を避けることを扱う。信頼性は障害への対応と復旧、持続可能性は環境への影響の削減の柱で、運用上の優秀性はむしろ運用の自動化を勧める。

第1章　問18

システムの部品同士を直接つなぐ代わりに、間にキューを置いて、片方が止まってももう片方が影響を受けにくくした。この設計の原則を何という？

  1. ア　垂直スケーリング
  2. イ　疎結合
  3. ウ　単一障害点の集約
  4. エ　オーバープロビジョニング
答えと解説を見る

正解：イ　疎結合

キューなどで部品同士の依存を弱め、1つの故障や遅延が全体に広がらないようにするのが疎結合。垂直スケーリングは1台の性能を上げること、オーバープロビジョニングは必要以上に用意することで、どちらも別の話。

第1章　問19

クラウドの設計の考え方「障害を前提に設計する（Design for failure）」に最も合っている構成はどれ？

  1. ア　高性能なサーバー1台にすべての処理を集める
  2. イ　障害が起きないよう、サーバーの設定を一切変更しない
  3. ウ　障害が起きたら担当者が手作業でサーバーを作り直す
  4. エ　複数のアベイラビリティーゾーンにサーバーを分け、1台が止まっても処理を続けられるようにする
答えと解説を見る

正解：エ　複数のアベイラビリティーゾーンにサーバーを分け、1台が止まっても処理を続けられるようにする

部品はいつか必ず壊れる前提で、複数のAZに分散して単一障害点をなくすのがこの原則。1台に集める構成は単一障害点になり、手作業の復旧は時間がかかり自動化の原則にも反する。

第1章　問20

負荷が増えたとき、サーバーをより大きなサイズに変えるのではなく、同じサイズのサーバーの台数を増やして対応する。これを何という？

  1. ア　水平スケーリング（スケールアウト）
  2. イ　垂直スケーリング（スケールアップ）
  3. ウ　リホスト
  4. エ　ライトサイジング
答えと解説を見る

正解：ア　水平スケーリング（スケールアウト）

台数を増やして負荷を分けるのが水平スケーリング（スケールアウト）。1台の性能を上げるのは垂直スケーリング（スケールアップ）で、上限があり単一障害点も残りやすい。リホストは移行戦略、ライトサイジングは適切なサイズへの見直し。
